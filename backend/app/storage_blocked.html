B3 Hive
Storage is not persistent — setup refused
B3 Hive detected that the data directory {{DATA_DIR}} is not on a persistent volume. The blockchain and any wallet you create here would be lost when the container is removed or updated.

This wallet cannot start safely

B3 Hive refuses to run on throwaway storage. No configuration, no wallet, and no blockchain data were written — nothing was created that could be lost.

Why this happened

The container's {{DATA_DIR}} directory sits on the container's temporary filesystem (overlay) or an anonymous Docker volume — not a bind mount or a named volume. When you run docker compose down or update the image, that storage disappears along with any wallet and chain data on it.

How to fix it

  1. Stop the container: docker compose down
  2. Add a persistent volume for /data — choose one of the options below.
  3. Start again: docker compose up -d — the setup wizard will appear normally.

Option A — Named volume (recommended)

Add a volume to your docker-compose.yml:

volumes:
  b3hive-data:

services:
  b3hive:
    volumes:
      - b3hive-data:{{DATA_DIR}}

Option B — Host directory bind mount

Map a directory on your host machine so you can see the files directly:

services:
  b3hive:
    volumes:
      - ./b3hive-data:{{DATA_DIR}}

Plain docker run equivalent: docker run -v b3hive-data:{{DATA_DIR}} ...

After adding the volume mapping and restarting, this page will disappear and the setup wizard will load. If you already configured a volume and still see this page, make sure the compose file in use is the right one (not a stale override) and that the mount source is a bind mount or a named volume, not an anonymous one.
